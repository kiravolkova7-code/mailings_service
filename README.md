# Mailing Service
## Описание:
Данный проект представляет собой веб-приложение для управления рассылками, администрирования и получения статистики.
Сервис позволяет создавать «прогревающие» рассылки для удержания клиентов бизнеса.

Проект реализован в виде `Django`-приложения с разделением функциональности по модулям: `mailings` (управление рассылками), 
`messages` (хранение шаблонов писем) и `recipients` (база получателей). В рамках второй части проекта добавлены аутентификация 
пользователей, разграничение прав доступа и кеширование данных через `Redis`.

## Функционал:
### V1 — Базовая функциональность
#### Модуль recipients («Получатели»)

* Модель `Recipient`: содержит уникальные поля для `email`-адреса получателя, ФИО и комментарий.


* `CRUD`-операции: реализованы стандартные действия через `Django Admin` или собственные страницы с формами:
Добавление нового получателя.
Просмотр списка всех получателей.
Редактирование данных существующего получателя.
Удаление получателя из базы.

#### Модуль messages («Шаблоны сообщений»)

* Модель `Message`: хранит тему письма (`subject`) и тело сообщения (`body`). Это универсальные шаблоны, которые можно 
использовать во множестве рассылок.


* `CRUD`-операции: аналогично получателям, доступны все операции управления сообщениями.

#### Модуль mailings («Рассылки»)
Это ключевой модуль сервиса. Он отвечает за планирование и отправку писем.

* Модель `Mailing`: включает обязательные поля `start_time`, `end_time` и внешний ключ на сообщение (`message_id`), 
а также связь «многие ко многим» со списком получателей (`recipients`).


* Статус рассылки: вычисляется динамически при каждом обращении к объекту:
Создана — текущая дата меньше даты начала `(datetime.now() < start_time)`.
Запущена — текущая дата находится между датами начала и окончания включительно` (start_time <= datetime.now() <= end_time)`.
Завершена — текущая дата больше даты окончания `(datetime.now() > end_time)`.


* Валидация: добавлены валидаторы полей:
Дата начала не может быть в прошлом.
Дата начала должна быть строго раньше даты окончания.


* Механизм отправки: реализован обработчик (через команду `manage.py send_mailing`):
Проверяется интервал времени. Если он разрешает отправку, запускается цикл по всем получателям данной рассылки.
Для каждого получателя вызывается метод `send_mail()` с использованием темы и тела из связанного объекта `Message`.
При успешной доставке создается запись о попытке с статусом «Успешно», при ошибке доставки — статус «Не успешно» и текст ошибки от почтового сервера.

#### Модуль attempts («Попытки отправки»)

* Модель `Attempt`: фиксирует каждую попытку отправки письма. Содержит дату/время попытки, ссылку на родительскую рассылку, 
статусы успеха или неудачи и ответ сервера.
Эта модель позволяет вести детальную статистику эффективности каждой кампании.


### V2 — Расширенная версия

#### Аутентификация и регистрация пользователей (`users`)

* Реализована стандартная система аутентификации `Django` с кастомными страницами входа и выхода.
* Пользователь может зарегистрироваться на сайте, подтвердив свой `email`-адрес (через встроенные механизмы `Django Allauth`).
* Восстановить пароль можно через форму восстановления с отправкой ссылки на почту.
* Права доступа и разграничение ролей
#### Проект использует систему групп и прав `Django`.

Пользователи (`Users`):
* Имеют доступ только к своим данным.
* Могут создавать, просматривать, редактировать и удалять свои личные рассылки, сообщения и получателей.
* Видят статистику только по своим рассылкам.

Менеджеры (`Managers`):
* Обладают правами просмотра всей информации в системе (все клиенты, все рассылки, статистика по ним).
* Не могут изменять чужие данные напрямую, но имеют право блокировать других пользователей и отключать их активные рассылки.

#### Статистика и отчеты

На главной странице приложения выводится общая аналитика:

* Общее количество созданных рассылок.
* Количество активных рассылок (статус «Запущена»).
* Число уникальных получателей (общее число клиентов в базе).

Для каждой конкретной рассылки доступна детализированная статистика:
* Количество успешных попыток отправки.
* Количество неуспешных попыток.
* Список ошибок почтовых серверов.


#### Кеширование (`Redis`)
Настроено кеширование на уровне представлений с помощью декоратора `@cache_page`. Результаты тяжелых запросов (например, 
список всех рассылок пользователя или главная страница с метриками) сохраняются в `Redis`.

Также используется кэширование сессий и авторизации для повышения производительности клиентской части.

#### Таким образом, проект представляет собой полноценный инструмент для автоматизации маркетинговых коммуникаций, который обеспечивает надежный контроль над процессом отправки писем, сбор статистики и управление пользователями.

## Установка
1. Клонируйте репозиторий:
```
git clone https://github.com/kiravolkova7-code/mailings_service.git
```
2. Создайте и активируйте виртуальное окружение:

Для Windows:
```
python -m venv venv
.\venv\Scripts\activate
```
3. Скопируйте шаблон файла окружения и заполните его своими данными:
```
cp .env.example .env
```
Заполните переменные  в файле `.env`. Шаблон заполнения находится в `.env_example`

4. Установите зависимости из файла:
```
pip install -r requirements.txt
```
5. Примените миграции:
```
python manage.py migrate
```
6. Запустите сервер разработки:
```
python manage.py runserver
```

## Зависимости
Все необходимые пакеты указаны в файле `requirements.txt`.


## Использование:
Запустите сервер разработки командой:

```
python manage.py runserver
```

Откройте сайт в браузере по адресу http://localhost:8000.
